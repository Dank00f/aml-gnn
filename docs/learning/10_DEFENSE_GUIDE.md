# 10. Defense Guide

## Короткий рассказ о проекте

«В рамках работы разработано веб-приложение для визуального анализа транзакционного графа в задачах AML и anti-fraud. Пользователь загружает CSV с транзакциями, backend строит ориентированный мультиграф счетов, запускает rule-based детекторы подозрительных паттернов, рассчитывает risk score, clustering и layout. Результат передаётся во frontend через SSE и отображается интерактивно через cosmos.gl».

## Сценарий демонстрации

1. Открыть главную страницу.
2. Загрузить CSV IBM формата.
3. Показать прогресс обработки.
4. Открыть страницу графа.
5. Показать число узлов и рёбер.
6. Показать группы AML-паттернов.
7. Включить risk filter.
8. Выбрать подозрительный узел.
9. Показать связанные транзакции.
10. Показать вкладку кластеров и metadata.
11. Открыть benchmark report.

## Возможные вопросы комиссии

| Вопрос | Короткий ответ |
|---|---|
| Почему граф? | Потому что AML-паттерны часто проявляются не в одной операции, а в связях между счетами |
| Почему MultiDiGraph? | Он сохраняет несколько транзакций между одной парой счетов, не перезаписывая операции |
| Risk score доказывает мошенничество? | Нет, это индикатор внимания аналитика |
| Используется ли `Is Laundering` в score? | Нет, label хранится отдельно и не используется в rule-based scoring |
| Почему ForceAtlas2/layout? | Layout нужен для читаемой визуализации структуры графа |
| Что делает clustering? | Группирует структурно связанные области графа для удобства анализа |
| Почему нет PostgreSQL/Redis/RabbitMQ? | Текущий MVP использует in-memory storage; внешняя инфраструктура является дальнейшим развитием |
| GNN готова? | Как runtime-функция нет; подготовлен experimental dataset и NumPy GCN baseline, inference не включён в MVP |
| Какие ограничения? | In-memory storage, CSV-only, нет промышленной масштабируемости, Docker не проверен в текущем окружении |

## Что можно утверждать

- Реализован MVP pipeline.
- Backend и frontend собираются.
- Backend tests проходят.
- Повторные транзакции сохраняются.
- Минимум четыре detector-группы покрыты тестами.
- Risk score находится в диапазоне `[0, 1]`.
- Benchmark подтверждён до 10 000 synthetic transactions на текущей машине.

## Что нельзя утверждать

- Нельзя утверждать production-ready масштабируемость.
- Нельзя утверждать работу на реальных банковских данных.
- Нельзя утверждать Excel upload.
- Нельзя утверждать готовую GNN модель.
- Нельзя утверждать Docker Compose как проверенный, пока он не запущен на машине с Docker.
